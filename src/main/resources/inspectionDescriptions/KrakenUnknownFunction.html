Reports a function call in a KEL expression that matches no known function.

Kraken identifies a function by its name and parameter count, not by parameter types, and resolves it from three places: the built-in Java functions, a Function declared with a KEL body, and a Function signature declared without a body (backed by a Java implementation). A call is reported only when none of the three matches.

When the name exists but not with that number of arguments, the message says which arities are declared instead of reporting an unknown name.

Declared functions follow the usual namespace visibility: a Function in a namespace this file does not Include is not a match, exactly as in the engine.

Project-specific native functions. The engine puts a Java function in scope automatically only when its FunctionLibrary is annotated @Native; anything else has to be declared with a Function signature, which this plugin already sees.

Those @Native libraries are found by reading the project's Java sources for @ExpressionFunction, so no configuration is needed in the common case. Because the Java signature is not analysed, such a function is accepted at any number of arguments.

What the scan cannot see — functions shipped inside a JAR, or implemented only in TypeScript, whose declaration form makes reliable detection impossible — can be listed by name in the inspection options.
