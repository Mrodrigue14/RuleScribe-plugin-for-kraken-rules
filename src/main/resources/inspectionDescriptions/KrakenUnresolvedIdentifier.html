Reports a bare identifier in a KEL expression that no scope defines.

Kraken stacks two scopes around a rule expression: a global one holding every context of the project, and a local one whose type is the context targeted by On, which makes its fields referable without a prefix. Variables introduced by the expression itself — set, for, every, some — and the parameters of an enclosing Function shadow both.

This inspection is deliberately conservative. The engine resolves identifiers with full type information; this plugin does not have it yet, so an identifier is reported only when its absence is certain. It stays silent on:

  • path segments (a.b.c) — without the type of a, nothing can be claimed about b;
  • rules whose On target does not resolve, since there is then no reference context to judge against;
  • context, the external-context root the engine always places in the global scope;
  • function call heads — not checked by any inspection.

The trade-off is intentional: this misses mistakes the engine catches, but it must never underline valid code.
